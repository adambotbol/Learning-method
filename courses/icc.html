FondamentauxÉcrire un algorithme

Exemple — « Machin »

Que sort Machin(7) ?

Machin
entrée : a, entier strictement positif
b ← 0 ; c ← 1 ; d ← 0
Tant que c < a
    d ← d + 1
    Si d est un multiple de 7 ou de 11
        b ← b + d
        c ← c + 1
Sortir : b
Solution

103 = somme des 6 premiers multiples communs de 7 ou 11 ($7+11+14+21+22+28$) — attention à l'inégalité stricte c < a.

Traduction C++ directe :

unsigned int f(unsigned int a) {
    unsigned int b(0), c(1), d(0);
    while (c < a) {
        ++d;
        if ((d % 7 == 0) or (d % 11 == 0)) {
            b += d;
            ++c;
        }
    }
    return b;
}
Erreurs classiques signalées dans les corrigés
  • Une fonction récursive doit return, pas seulement affecter une variable.
  • Confondre l'affectation d'une liste entière et l'ajout d'un élément.
  • Accès hors bornes classique : comparer L[i] à L[i+1] jusqu'au dernier indice.
  • Oublier d'incrémenter la variable de contrôle d'une boucle Tant que → non-terminaison.

FondamentauxComplexité algorithmique

Convention du cours : opérations arithmétiques, taille d'une liste et accès à un élément sont $\Theta(1)$ ; on parle de complexité temporelle pire cas, notée $C(n)$ en fonction de la taille $n$ de l'entrée — bien définir $n$ est souvent la moitié du travail.

Exercice — « chiffres », récursion + équation de récurrence 
chiffres
entrée : nombre entier p
Si p < 0
    Sortir : 1 + chiffres(−p)
Si p < 10
    Sortir : 1
Sortir : chiffres(⌊p/10⌋) + 1

Donner la complexité.

Solution

$\texttt{chiffres}(-486)=1+\texttt{chiffres}(486)=1+((\texttt{chiffres}(4)+1)+1)=4$. Pour $p\ge0$, l'équation de récurrence est $T(n)=T(n/10)+\Theta(1)$, donc $T(n)\in\Theta(\log n)$ avec $n=|p|$. Remarque du corrigé : si l'on prend $n=\log|p|$ (la taille de la représentation de $p$), la complexité devient $\Theta(n)$ — très peu de copies traitent la complexité formellement ; méthode recommandée : équation de récurrence plutôt qu'arbre d'appels.

Exercice — « testeListe », optimisation Θ(n²) → Θ(n) 
testeListe
entrée : liste L de nombres entiers positifs
n ← taille(L)
Pour i de 1 à n−1
    Pour j de i+1 à n
        Si L[i] > L[j]
            Sortir : « non »
Sortir : « oui »
Solution

Pour $(2,5,4,6)$ : sortie « non » (couple $5>4$) — l'algorithme teste si la liste est triée. Complexité : double boucle imbriquée, $\sum_{i=1}^{n-1}(n-i)\in\Theta(n^2)$.

Optimisation en $\Theta(n)$ : comparer chaque élément à son seul successeur immédiat :

Pour i de 1 à n−1
    Si L[i] > L[i+1]
        Sortir : « non »
Sortir : « oui »
Exercice — récursion terminale simple 
int g(int n, int x, int y) {
    if (n <= 0) return x;
    return g(n-1, x+y, y);
}
int f(int n) { return g(n, 0, 3); }

Calculer $f(3), f(5)$, l'expression générale et la complexité.

Solution

$f(3)=9$, $f(5)=15$. Par récurrence, $g(n,x,y)$ retourne $x+ny$ pour $n\ge0$, donc $f(n)=3n$. Complexité $\Theta(n)$ : $n+1$ appels, chacun $\Theta(1)$ hors récursion. Piège : « faire quelque chose $n$ fois » ne garantit $\Theta(n)$ que si le corps est bien $\Theta(1)$.

FondamentauxRécursivité

Exercice — intersection récursive de listes triées

L1, L2 triées, sans doublons. Intersection récursive, sans boucle :

intersecR
entrée : L1, L2
Si L1 est vide ou L2 est vide
    Sortir : ()
Si L1(1) = L2(1)
    Sortir : L1(1) ⊕ intersecR(L1(2..), L2(2..))
Si L1(1) < L2(1)
    Sortir : intersecR(L1(2..), L2)
Sortir : intersecR(L1, L2(2..))
Solution

Complexité $\Theta(n)$ : chaque appel diminue la longueur d'au moins une des deux listes, au plus $2n$ appels. Pièges signalés (« très peu réussi ») : mauvais cas de base (renvoyer L1 ou L2 au lieu de la liste vide), mauvaise gestion du retour d'appel récursif, oubli de distinguer les cas $L1(1)$.

Exercice — Plus Longue Sous-Séquence Commune (PLSC)

Définition : $f(i,j)=0$ si $i=0$ ou $j=0$ ; $f(i-1,j-1)+1$ si $X[i]=Y[j]$ ; $\max(f(i,j-1),f(i-1,j))$ sinon.

Solution — version récursive naïve, exponentielle 
PLSCAnnexe(X, Y, i, j)
Si i = 0 ou j = 0 : Sortir 0
Sinon si X[i] = Y[j] : Sortir PLSCAnnexe(X,Y,i−1,j−1) + 1
Sinon : Sortir max(PLSCAnnexe(X,Y,i,j−1), PLSCAnnexe(X,Y,i−1,j))

Équation de récurrence (pire cas) : $T(i,j)=T(i,j-1)+T(i-1,j)+\Theta(1)$. En posant $k=i+j$ : $S(k)=2S(k-1)+\Theta(1)\in\Theta(2^k)$, donc avec $i=j=n$ : $T\in\Theta(2^{2n})$, exponentiel.

Solution — version dynamique, $\Theta(n^2)$ 
PLSCDynamique(X, Y)
n ← taille(X) ; m ← taille(Y)
f ← matrice (n+1)×(m+1), initialisée à 0 sur les bords
Pour i de 1 à n
    Pour j de 1 à m
        Si X[i] = Y[j] : f[i,j] ← f[i−1,j−1] + 1
        Sinon : f[i,j] ← max(f[i,j−1], f[i−1,j])
Sortir : f[n,m]

Double boucle $n\times m$ en $\Theta(1)$ chacune $\to\Theta(n^2)$ — un cas d'école de programmation dynamique, proche des coefficients binomiaux vus en cours.

Exercice — fusion triée et fusion alternée récursives
Solution 
// fusion triée récursive — Θ(n)
liste fusion_triee(liste& L1, liste& L2) {
    if (L1.empty()) return L2;
    if (L2.empty()) return L1;
    liste retour;
    auto valeur(L1.back());
    if (L1.back() > L2.back()) { L1.pop_back(); }
    else { valeur = L2.back(); L2.pop_back(); }
    retour = fusion_triee(L1, L2);
    retour.push_back(valeur);
    return retour;
}

// fusion alternée récursive
liste fusion_alt_rec(liste& L1, liste& L2) {
    if (L1.empty()) return L2;
    if (L2.empty()) return L1;
    const auto first(L1.back());  L1.pop_back();
    const auto second(L2.back()); L2.pop_back();
    liste retour(fusion_alt_rec(L1, L2));
    retour.push_back(first);
    retour.push_back(second);
    return retour;
}

Complexité $\Theta(n)$ où $n$ = taille totale, chaque liste étant parcourue une seule fois.

FondamentauxListes et structures de données

Exercice — intersection de listes, trois approches comparées
Solution

(a) Naïve, $\Theta(n^2)$ — double boucle comparant chaque élément de L1 à chaque élément de L2.

(b) $\Theta(n\log n)$ — trier L1 puis rechercher dichotomiquement chaque élément de L2 (tri en $\Theta(n\log n)$ + $m$ recherches en $\Theta(\log n)$).

(c) $\Theta(n)$ — la version récursive intersecR ci-dessus, sur listes déjà triées.

Commentaire du correcteur : « l'appartenance d'un élément à une liste n'est pas une opération élémentaire » — piège classique de considérer $x\in L$ comme $\Theta(1)$, de même pour la concaténation de deux listes.

struct Ordinateur {

calculer_opmoyen(Ordinateur) : moyenne des capacités des processeurs. allocation(liste<Ordinateur>, liste<Tache>) : algorithme glouton — chaque tâche est affectée au premier ordinateur dont les ressources restantes suffisent, puis les ressources restantes sont mises à jour par soustraction.

Exercice — régression linéaire (structures Point/Line)
Solution 
struct Point { double x; double y; };
struct Line  { double a; double b; };   // y = a*x + b
typedef vector<Point> Cloud;

Line fit(Cloud const& data) {
    if (data.empty()) return { 0.0, 0.0 };
    double Sxy(0.0), Sx2(0.0), Sx(0.0), Sy(0.0);
    for (auto p : data) {
        Sxy += p.x * p.y; Sx2 += p.x * p.x;
        Sx += p.x; Sy += p.y;
    }
    const double diviseur(Sx2 - (Sx*Sx)/data.size());
    if (abs(diviseur) <= 1e-12) return { 0.0, 0.0 };
    const double a((Sxy - (Sx*Sy)/data.size()) / diviseur);
    return { a, (Sy - a*Sx)/data.size() };
}

double mse(Line const& line, Cloud const& data) {
    if (data.empty()) return 0.0;
    double s(0.0);
    for (auto p : data) {
        const double val(p.y - (line.a * p.x + line.b));
        s += val * val;
    }
    return s / data.size();
}

Bon exemple de manipulation combinée struct + vector + boucle unique + gestion d'un cas limite (division par $\approx0$).

FondamentauxReprésentation binaire des nombres

Thème quasi systématique en première question des deux examens intermédiaires lus.

Virgule flottante — décodage

Nombre binaire 0100100110 sur 10 bits (1 signe + 3 exposant + 6 mantisse).

Solution

Signe 0 (positif), exposant 100=4, mantisse 100110 → $1{,}100110\times2^4=11001{,}1_2=$ 25.5.

Complément à deux — encodage d'un négatif

int i(-54) sur 8 bits ?

Solution

$54=$ 00110110 → inverser tous les bits puis $+1$ → 11001010 (équivalent à $256-54=202$ en binaire non signé).

Bits nécessaires pour une opération sans dépassement

$m$ sur $p$ bits non signés, $n$ sur $q$ bits. Bits nécessaires pour $m\times n$ et $m+n$ ?

Solution

$m\times n$ : $p+q$ bits ($m\times n<2^p\cdot2^q=2^{p+q}$). $m+n$ : $\max(p,q)+1$ bits. Piège signalé : beaucoup pensent à tort que le maximum représentable sur $p$ bits est $2^p$ (c'est $2^p-1$).

FondamentauxDébogage et tests

Exercice — « Zébrons », trouver des tests puis corriger

Détecter des variations anormales (>10) dans des mesures, en ignorant les capteurs à 0 :

constexpr int TOLERANCE = 10;
vector<size_t> monitoring(vector<int> mesures) {
    vector<size_t> resultat;
    for (size_t i = 0; i + 1 < mesures.size(); i++) {
        int elemCourant = mesures.at(i);
        int elemSuivant = mesures.at(i + 1);
        if (elemCourant == 0) { /* déjà traité */ }
        else if (elemSuivant != 0) {
            if (abs(elemSuivant - elemCourant) >= TOLERANCE)   // bug
                resultat.push_back(i + 1);
        } else {
            int elemSuivantSuivant = mesures.at(i + 2);          // bug
            if (abs(elemSuivantSuivant - elemCourant) > TOLERANCE)
                resultat.push_back(i + 2);
        }
    }
    return resultat;
}
Solution

Trois tests, un par catégorie de bug :

Faux positif{5,15}attendu {}obtenu {1}
Faux négatif{5,0,0,20}attendu {3}obtenu {}
Crash{5,0}attendu {}crash (accès hors bornes)

Corrections : >= doit être > ; il faut une boucle sautant tous les zéros consécutifs (pas seulement un) tout en vérifiant les bornes à chaque pas :

size_t j = i + 2;
while (j < mesures.size() && mesures.at(j) == 0) { j++; }
if (j < mesures.size() && abs(mesures.at(j) - elemCourant) > TOLERANCE)
    resultat.push_back(j);

Commentaire du correcteur : beaucoup de copies inventent de fausses erreurs (changer un type de retour, par exemple) — un code donné par l'énoncé comme fonctionnel ne doit pas être suspecté d'erreurs de compilation.

FondamentauxMachines de Turing

Exercice type — reconnaître $0^n1^n$

Table de transition à 6 états, appliquée à la bande 0 0 0 0 1 1 1 1.

Solution — méthode

Les états 1/2/3 parcourent la bande de gauche à droite en effaçant, cyclant à chaque 0 vu ; si l'on retombe sur une case vide dans l'état 1 (multiple de 3 zéros), on va chercher un 1 en fin de bande pour l'effacer, puis on recommence. Conclusion : la machine vérifie si l'entrée est de la forme $0^n1^n$ (même nombre de 0 que de 1). Piège : beaucoup concluent à tort que la machine « efface tout » — impossible puisque tout arrêt de cette machine écrit quelque chose avant de s'arrêter.

Méthode générale pour ce type d'exercice

Simuler « au crayon » la machine, repérer les cycles d'états qui parcourent/effacent la bande, identifier ce qui déclenche un changement de branche (souvent une condition modulo un petit nombre), puis formuler en une phrase la fonction globale en justifiant le rôle de chaque groupe d'états — y compris un éventuel état de simple « repositionnement » de la tête avant l'arrêt, souvent oublié dans les copies.

FondamentauxComplexité NP, certificats, SAT / SSP

SAT — satisfaisabilité booléenne

Entrée : une formule booléenne. Sortie : satisfiable ou non (+ une assignation satisfaisante = le certificat).

Pourquoi SAT ∈ NP

Toute formule se transforme (taille linéaire) en forme normale conjonctive équisatisfiable ($\wedge$ de $\vee$ de littéraux). Vérifier une assignation donnée coûte alors $\Theta(n)\times\Theta(n)+\Theta(n)=\Theta(n^2)$ — polynomial, donc SAT $\in$ NP. Piège signalé : confondre « vérifier » (polynomial → NP) et « résoudre » (pas nécessairement polynomial).

// résolution par force brute
SAT_solver(F) :
n ← nb_var(F)
Pour i de 0 à 2ⁿ − 1
    L ← assignation(i, n)
    Si évalue(F, L) : Sortir L
Sortir ()

Complexité : boucle en $\Theta(2^n)$, chaque évaluation polynomiale → au moins $\Theta(2^n)$, exponentielle. Piège : confondre le nombre de variables $n$ et la taille de l'espace de recherche $2^n$.

SSP — sous-ensemble de somme nulle

Ex : $\{3,4,12,-1,6,-2\}\to$ « oui » ($\{3,-1,-2\}$ somme à 0) ; $\{3,2,14,-8,1\}\to$ « non ».

Solution

Résolution (par force brute, $k$ codant un sous-ensemble en binaire) :

SSP(E) :
n ← taille(E) ; maxK ← 2ⁿ−1
Pour k de 1 à maxK
    Si somme(E,k) = 0 : Sortir « oui »
Sortir « non »

Complexité : $(2^n-1)$ itérations $\times\ \Theta(n)$ par appel à somme → $\Theta(n\cdot2^n)$, exponentielle. Ce n'est pas contradictoire avec SSP $\in$ NP : NP ne dit rien sur la complexité de résolution, seulement de vérification.

Vérification (certificat = le sous-ensemble codé par $k$), en $\Theta(n)$ :

VérifieSSP(E, k) :
Si k < 1 ou k > 2^taille(E) − 1 : Sortir « non »
s ← 0
Pour i de taille(E) à 1 en descendant
    Si k est impair : s ← s + E[i]
    k ← ⌊k/2⌋
Sortir « oui » si s = 0, sinon « non »

Vérification polynomiale ($\Theta(n)$) — cohérent avec SSP $\in$ NP.
