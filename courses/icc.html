FondamentauxComplexité algorithmique

La complexité $C(n)$ compte le nombre d'opérations fondamentales en fonction de la taille $n$ de l'entrée, avec les notations $\Theta$, $O$, $\Omega$. Classes usuelles, de la plus rapide à la plus lente :

  • constante — $O(1)$
  • logarithmique — $O(\log n)$ (dichotomie)
  • linéaire — $O(n)$
  • polynomiale — $O(n^2), O(n^3), \dots$
  • quasi-linéaire — $O(n\log n)$
  • exponentielle — $O(2^n)$
Exemple travaillé : compter les chiffres d'un entier

Une fonction récursive chiffres(p) qui compte les chiffres d'un entier $p$ vérifie l'équation de récurrence $T(n) = T(n/10) + \Theta(1)$, d'où $T(n) \in \Theta(\log n)$.

Le piège méthodologique

Il faut bien définir ce qu'est « $n$ » : si $n=|p|$ (la valeur de l'entier) plutôt que $n=\log|p|$ (le nombre de chiffres), la complexité s'exprime différemment. Une erreur classique du cours est de confondre le nombre d'itérations d'une boucle avec sa complexité totale — celle-ci dépend aussi de la complexité du corps de la boucle.

Fondamentaux — dernier vuRécursivité en C++

Exemple complet et représentatif : le calcul de $1/e$ par sa série entière, $\dfrac1e = \sum_{k=0}^\infty \dfrac{(-1)^k}{k!}$.

double factorielle(double n) {
    if (n <= 1.0) return 1.0;
    return n * factorielle(n - 1.0);
}

// version efficace, Θ(n) : chaque terme se déduit du précédent
double approx_inv_e(double n) {
    double term(1.0), res(term);
    for (double i(1); i <= n; ++i) {
        term = -term;
        term /= i;
        res += term;
    }
    return res;
}

// version naïve : recalcule factorielle(k) à chaque terme → Θ(n²)

void affiche_inv_e() {
    int n(-1);
    do {
        cout << "Entrez un entier strictement supérieur à 1 : ";
        cin >> n;
    } while (n <= 1);

    for (int i(2); i <= n; ++i)
        cout << "ordre " << i << " : " << approx_inv_e(i) << endl;
}
Ce que cet exemple enseigne

Deux implémentations du même calcul peuvent avoir des complexités très différentes : la version qui recalcule factorielle(k) à chaque terme de la somme est en $\Theta(n^2)$, alors que la version qui met à jour le terme précédent est en $\Theta(n)$. C'est l'illustration centrale du lien entre complexité et façon d'écrire le code, pas seulement l'algorithme sur le papier.
